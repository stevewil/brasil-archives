## 1. Ecosystem overview

The Brasil Archives Project is a three-repo system:

| Repo | Role | Deploy target | Status |

| **[stevewil/brasil-archives](https://github.com/stevewil/brasil-archives)** | Metadata catalog + scoring + federation aggregator | `https://brasil-archives.from-bottom-to.top` (cPanel) | Phase 3 shipped; UI polish in progress |
| **[stevewil/mipibu](https://github.com/stevewil/mipibu)** | São José de Mipibu judicial corpus explorer | `https://mipibu.from-bottom-to.top` (cPanel) | Live, OAI-PMH endpoint verified |

**Relationship:**

- `brasil-archives` is the **aggregator**. Public-facing catalog of Brazilian digital archives with a scoring algorithm, and the federation counterpart that harvests from partner corpus explorers.
- `mipibu` and `povos-indigenas-rn` are **partner corpus explorers** — deep-dive apps for specific archives. They register with `brasil-archives` as "upgrade projects" and expose their content via a federation contract (JSON API + eventually OAI-PMH).
- The federation contract lives in [`brasil-archives/docs/federation-v1.md`](../federation-v1.md).
- `mipibu` is the reference implementation; `povos` is the second-caller that will trigger extraction of shared code (see §5).

## 2. Standing constraints (preserve verbatim)

These are non-negotiable across every session. They come from prior conversations with the user and multiple sessions have validated them.

- **Bilingual PT/EN throughout.** Everything user-facing must render in both.
- **National-period historian focus** (1800–1900). Age-as-value bias is **rejected**; a 1960s archive is not automatically less valuable than an 1860s one.
- **Nordeste focus.** RN, PE, BA are primary; ecclesiastical sources are important; resource-poor archives are supported, not filtered out.
- **Fair use / uso justo is the fundamental floor.** Every archive on the public site must clear this bar. Terminology: use "uso justo," not "uso legítimo."
- **`brasil-archives` = metadata of archives.** It is separate from `mipibu`-style corpus explorers. Don't mix corpus data into brasil-archives; don't mix archive catalog data into a corpus explorer.
- **Licensing:** MIT/Apache for code, CC-BY-SA for data.
- **Pull-only cPanel, never push.** All cPanel deploys pull from GitHub. Never SCP, rsync, or SFTP code up.
- **Wasabi keys stay on workstation only** — never sent over chat. All Wasabi buckets in `us-west-2`.
- **Design 2:** local is primary, Wasabi is distribution, cPanel is public mirror.
- **Cache TTL: 15 minutes hardcoded** (`CACHE_TTL_SECONDS = 900`).
- **Lazy fetch** on page render (not background refresh).

## 5. UI polish: token-efficient tooling proposal

**Context:** During the 2026-08-27 session the user asked why UI polish tracks cost so many tokens. The honest answer is that most cost is in reading templates, rewriting them, and reasoning about design decisions — with meaningful savings available from tooling. The user endorsed the proposal.

### The tooling to build before Tracks 1, 2, and 5

Landing these three scripts first is estimated to save 40–80k tokens across the remaining polish work.

**1. `scripts/dev/session_state.sh` — session bootstrap digest**

Prints a compact digest of current state so the next session doesn't spend ~5k tokens re-discovering it:

```bash

echo
echo "=== DB counts ==="
DATABASE_URL=sqlite:////home/user/workspace/brasil-archives/instance/brasil_archives.db \

from app import create_app
```

**2. `scripts/dev/wrap_i18n.py` — codemod for Track 1**

Walk templates, wrap bare text nodes in `{{ _(...) }}` where safe. Rules:
- Skip URL attributes, class names, id attributes
- Skip nodes inside existing `{{ _() }}` or `{% trans %}` blocks
- Skip nodes matching pure-punctuation regex (`—`, `·`, numbers alone)
- Emit a diff for review before applying; only apply on `--apply`

Estimated savings: 30–50k tokens on Track 1 alone (the ~100 mechanical string wraps).

**3. `tests/test_template_hygiene.py` — grep-based template linter**

```python
"""Guardrails against regressions in template patterns."""
from pathlib import Path
import re

TEMPLATE_DIR = Path(__file__).parent.parent / "app" / "templates"


def _templates():
    return list(TEMPLATE_DIR.rglob("*.html"))


def test_no_direct_label_en_access():
    """After Track 4, templates must use vocab_label() not .label_en."""
    bad = []
    pattern = re.compile(r"\.label_(en|pt)\b")
    for tpl in _templates():
        for i, line in enumerate(tpl.read_text().splitlines(), 1):
            if pattern.search(line):
                bad.append(f"{tpl.relative_to(TEMPLATE_DIR)}:{i}: {line.strip()}")
    assert not bad, "Use vocab_label(x) instead of x.label_*:\n" + "\n".join(bad)


def test_no_inline_style_attributes():
    """Detail template inline styles should live in style.css. Guardrail
    for Track 5 — extend the exception list only when there's a genuine
    reason (e.g. dynamic width from a scored value)."""
    bad = []
    for tpl in _templates():
        for i, line in enumerate(tpl.read_text().splitlines(), 1):
            if 'style="' in line and "{{" not in line.split('style="', 1)[1].split('"', 1)[0]:
                bad.append(f"{tpl.relative_to(TEMPLATE_DIR)}:{i}")
    # Uncomment when Track 5 lands. Until then this would fail on
    # detail.html's upgrade-projects section.
    # assert not bad, "Inline styles found — move to style.css:\n" + "\n".join(bad)
```

Estimated savings: prevents ~2-3 round-trips per polish task where I currently have to re-scan templates for regressions.

### Why more can't be automated

- **Editorial judgment cannot be scripted.** Whether a scoring form should be public or admin-only is a design call. Whether "fair use" translates as "uso justo" or "uso legítimo" is an editorial call (project already says "uso justo").
- **Template semantics beyond text nodes.** Some strings sit inside attributes, some are macro parameters. A codemod that gets 80% right is a huge win; getting 100% requires per-case review.
- **Cross-session context reset.** The `session_state.sh` digest helps a lot, but never to zero. The next agent still has to load and reason about the codebase.

### Recommended next-session flow

1. Land the three scripts as a discrete commit (`chore(dev): tooling for token-efficient polish work`).
2. Run `bash scripts/dev/session_state.sh` first thing every session.
3. Track 5 next (small, visible, tests the tooling).

## 7. cPanel pull workflow (verified 2026-08-27)

**All three apps deploy the same way.** No build step, no Node, no background workers.

### Deploying a new commit

1. In sandbox / local: `git commit && git push origin main` (uses `api_credentials=["github"]`).
2. On cPanel terminal:
   ```bash
   cd ~/<app-dir>   # e.g. ~/brasil-archives or the mipibu path
   git fetch origin
   git pull origin main
   ```
3. Restart Passenger:
   - `touch tmp/restart.txt`  **or**
   - cPanel UI → **Setup Python App → <app> → Restart**
4. Verify:
   ```bash
   curl -s https://<app>.from-bottom-to.top/healthz
   ```

## 8. Gotchas discovered this session

### Adding povos as an upgrade_project

Attempted 2026-08-27. **Blocked, deferred**, but the analysis is preserved:

- `delivery_status` is editorially enforced as `in-development | beta | stable | deprecated`. No `scaffold` option.
- `source_archive_id` on `upgrade_projects` is NOT NULL. Every upgrade project must reference a row in `archives`.
- **The archives table has no row for povos's source.** The Nordeste digital archives survey doesn't include an Indigenous-history archive. Povos is *both* an archive of assembled evidence *and* the tool that presents it — but until it's cataloged as an archive, it can't be registered as an upgrade project.
- **Recommended path when the time comes:**
  1. Add an `archives` row: `name="Povos Indígenas do RN — corpus"`, `institutional_type=research-project`, `home_state_code=RN`, `no_digital_content=False`, `canonical_url=<future deploy URL>`.
  2. Once povos has an OAI-PMH endpoint working (Track B), add `configs/upgrade_projects/povos-indigenas-rn.yaml` (see `configs/upgrade_projects/mipibu.yaml` for shape).
  3. Run `python -m scripts.load_upgrade_projects` — idempotent, upserts by slug.
  4. Pull to cPanel. Counter goes 1 → 2 legitimately.
- **Handoff doc explicitly says:** register only after `/oai` works. That's still the right call.

### Sandbox cloud browser can't reach `localhost:5001`

Cloud browser sessions are isolated from the sandbox's localhost bindings. When needing to see rendered HTML, use `curl` from `bash` instead — the tool actually needs is a headed browser only for interaction, not for viewing static output.

### Server started with `--no-reload` doesn't pick up Python changes

Templates auto-reload, but changes to `app/__init__.py` (like registering a new Jinja global) require an explicit restart. If you see `UndefinedError: 'foo' is undefined` after adding a global, restart the server:

```bash
pplx-tool start_server <<'JSON'
{"command": "bash /tmp/ba-start.sh", "project_path": "/home/user/workspace/brasil-archives", "port": 5001, "log_file": "/tmp/ba.log"}
JSON
```

with `api_credentials=["pplx-tool:start_server"]`.

### pybabel extraction must run from repo root

`babel.cfg` uses the pattern `[jinja2: app/templates/**.html]`. Running `pybabel extract` from `app/` misses the template files silently. Always run from repo root.

- **Don't push directly to cPanel.** Always through GitHub. §7.
- **Don't send Wasabi keys over chat.** They stay on the user's workstation.

- **Don't scope-creep across tracks.** Each track is small and independent for a reason.
